- (decision) TOPOLOGY: one Encore app, ONE Postgres database, THREE domain services - charting, catalog, collection. Each service is the SOLE WRITER of its own tables; cross-domain access is read-only SQL. The seam is write authority, not network separation. Prevents: Tool endpoints in the App hot path; App writes to roster; two owners of one table. Chosen over hard 2-DB seam (plumbing, no cross-joins) and folder-convention modules (seam unenforced).
- (decision) TOOL UI PLACEMENT: one Vite+React frontend, two route worlds - binder/ (cozy, UX spine governs) and charting/ (utilitarian). One shared generated Encore client. Chosen over second Vite app (2 dev servers, mothballed rot) and CLI-only (700+ explainer throughput needs a real review queue UI).
- (decision) SLOT ADDRESSING: chase state references derived Slots by natural key (species, rung) with rung = stars 0..6, 0 = catch slot. Orphaned chase rows (roster fix removed the slot) are SURFACED, never auto-deleted - a Filled orphan is a physical card the chronicle no longer explains. Fill relation is slot -> N cards (join table) from day one; UI enforces 1 for now. Keeps ADR-0003 intact: nothing derived is stored, only references to derivable addresses.
- (decision) ERRATA MECHANISM: App-side snapshot diff. Collection service stores last-acknowledged binder digest; at open it diffs against the freshly computed binder to produce the errata slip (N entries changed + what moved). Chosen over Tool-side changelog (couples Tool to App, misses out-of-band hand-edits during mothball) and version-stamp-only (under-delivers UX). Roster version stamp remains as the cheap change signal.
- (decision) ELIGIBILITY: (1) ALL rarity->tier knowledge lives in the Rarity Translation Map table - no rarity string hardcoded in TS; UNKNOWN-mapped cards reported at ingestion and held out of eligibility (FR-026). (2) Species matching resolved at INGESTION into a normalized National Dex number column on catalog rows - no name parsing at query time. Eligibility is a catalog-side SQL query; the rank engine never learns what a card is.
- (decision) LLM PIPELINE: batch, inside the charting service. Charting service owns ALL Claude API calls; key in Encore secret, never client-side. Sources stored with MediaWiki revision id + content hash (durable citations + sticky-verdict change detection). Batch drafting job per Milestone type pre-populates the review queue. Chosen over on-demand (stalls review rhythm, breaks bulk-accept) and outside-the-app Claude Code scripts (does not survive mothballing).
- (decision) RENDERING: WebGL SCENE - user overrode the DOM+CSS recommendation, choosing the highest ceiling for ritual fidelity (cover, page-turn, sleeving, light). Consequence to resolve: text/links/a11y strategy for content inside card frames; HUD chrome stays DOM. Follow-up fork dispatched on the exact hybrid line.
- (decision) FRONTEND DATA DISCIPLINE: all server data through the ONE generated Encore client, wrapped in a single server-state layer (TanStack Query). No hand-rolled fetch in either route world. Client regenerated on every endpoint change (existing repo rule).
- (decision) OPS ENVELOPE: local-only forever (ADR-0004) - no deploy target ever. Dev = encore run + Vite dev server, Docker Desktop prereq. CI = GitHub Actions, typecheck + all tests. Roster JSON export = charting-service endpoint invoked via npm script, output committed to repo (the backup ritual).
- (decision) SCENE ARCHITECTURE: React Three Fiber + drei. GL owns the binder world (pages, cards, light, page-turn, sleeving). Interactive text inside card frames = drei Html (real DOM projected into 3D, links/selection work). Search bar + hover HUDs = DOM overlay outside the canvas. A11y = parallel DOM tree; reduced-motion = cuts instead of animations. One React tree end to end. Chosen over vanilla three.js (hand-built bridge, two paradigms) and all-GL text (rebuilds links/selection/screen-reader by hand).
- (decision) RUNG ATTRIBUTION (new pure engine capability): the k-th rung of an Entry is attributed to the k-th earned Milestone TYPE in canonical ruleset order (opponent, teammate, encounter, bond, glory, loyal). Story row shows ALL Milestone records of that type, flipping when >1. Badge Region tie-break: earliest record of the type is the earning one. Cashes both UX assumptions (story-row slot-milestone mapping, badge rule) by construction; stays derived per ADR-0003.
- (decision) CARD IMAGES: lazy local disk cache via the catalog service. Frontend only ever requests the catalog service; it fetches from the CDN once on first view, caches to disk, serves forever. Survives the pokemontcg.io->Scrydex CDN migration and mothballing; personal-use posture per ADR-0004. Chosen over hotlinking (binder hostage to flaky CDN) and eager full mirror (heavy, mostly wasted).
